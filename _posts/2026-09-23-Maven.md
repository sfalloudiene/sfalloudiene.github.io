Dans cet article, je vais faire un resume de maven qui est un outil de gestion de projet et de son utilisation.
<!--more-->

## Qu'est-ce que Maven ?

- **Maven** est un **outil de gestion de projet Java** (et autres langages JVM).
- Son rôle principal :
  - Compiler ton projet.
  - Gérer automatiquement les dépendances (bibliothèques externes).
  - Standardiser la structure et les builds des projets.
- Il automatise tout ce qui est répétitif dans un projet Java.

---

## Pourquoi l'utiliser ?

- Évite de télécharger manuellement les librairies.
- Standardise la structure des projets.
- Facilite l'automatisation des tests, builds, et packaging.
- Gère les conflits de versions ("jar hell").
- Compatible avec CI/CD (intégration continue).

---

## Structure d'un projet Maven

```
mon-projet/
│
├── pom.xml             # fichier principal, "recette de build"
└── src/
    ├── main/
    │   ├── java/       # code source
    │   └── resources/  # fichiers config
    └── test/
        ├── java/       # tests unitaires
        └── resources/  # fichiers de test
```

- `pom.xml` : cœur du projet, décrit les dépendances, plugins, et informations du projet.
- `src/main/java` : ton code source.
- `src/test/java` : tests unitaires (JUnit, TestNG, etc.).

---

## Le `pom.xml` expliqué

- **groupId** : identifie ton organisation ou package.
- **artifactId** : nom du projet.
- **version** : version actuelle (`SNAPSHOT` = en développement).
- **packaging** : type de build (jar, war, pom…).
- **parent** : permet d'hériter de configurations communes.
- **dependencies** : bibliothèques externes utilisées. Maven les télécharge automatiquement.
- **plugins** : extensions pour automatiser des tâches (ex : compilation JS, packaging).
- **profiles** : configurations alternatives pour modifier le build selon le contexte (ex : skip tests, déploiement).

---

## Cycle de vie Maven

- Maven possède un **cycle de vie prédéfini** :
1. `validate` : vérifier la configuration du projet.
2. `compile` : compiler le code source.
3. `test` : exécuter les tests unitaires.
4. `package` : assembler le projet (jar, war…).
5. `install` : installer le projet localement pour qu'il puisse être utilisé par d'autres projets.
6. `deploy` : publier sur un dépôt externe (ex : Nexus, Artifactory).

---

## Commandes Maven essentielles

| Commande | Description |
| --- | --- |
| `mvn clean` | Supprime les fichiers compilés. |
| `mvn compile` | Compile le code source. |
| `mvn test` | Exécute les tests unitaires. |
| `mvn package` | Crée un jar/war exécutable. |
| `mvn install` | Installe le projet dans le dépôt local. |
| `mvn dependency:tree` | Affiche toutes les dépendances et leurs sous-dépendances. |

---

## Dépendances et gestion automatique

- Tu ajoutes simplement la dépendance dans le `pom.xml`.
- Exemple :

```xml
<dependency>
    <groupId>org.apache.commons</groupId>
    <artifactId>commons-lang3</artifactId>
    <version>3.13.0</version>
</dependency>
```

- Maven télécharge **le jar et toutes ses dépendances automatiquement**.

---

## Plugins

- Les plugins sont des **extensions pour Maven** qui ajoutent des fonctionnalités.
- Exemple dans ton projet :
  - **frontend-maven-plugin** : exécute Node.js et npm depuis Maven (lint, tests JS).
  - **maven-assembly-plugin** : crée des distributions (zip, tar…) du projet.

---

## Profils

- Les profils permettent de **changer le comportement du build**.
- Exemples dans ton POM :
  - `skipTests` → ignorer les tests si besoin.
  - `siteclouddeploy` → configurer le déploiement sur un cloud.

---

## ️Infos supplémentaires importantes

- **SNAPSHOT vs RELEASE** :
  - `SNAPSHOT` → version en développement.
  - `RELEASE` → version stable publiée.
- **Héritage de parent** : très utilisé pour centraliser les versions et plugins dans une organisation.
- **Propriétés** : variables réutilisables dans le POM, pratiques pour la CI/CD ou les versions de Node.js.
- **Packaging POM** : utile pour des projets qui regroupent plusieurs modules (comme ton projet Playwright).

---

## En pratique

Pour un projet complet, le flux classique est :

1. `mvn clean` → nettoyer.
2. `mvn compile` → compiler.
3. `mvn test` → tester.
4. `mvn package` → créer le jar/war.
5. `mvn install` → installer localement.
6. `mvn deploy` → envoyer sur un serveur distant (optionnel).
